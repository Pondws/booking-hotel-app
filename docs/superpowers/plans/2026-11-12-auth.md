# Auth & Roles (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add session-cookie auth. Customers register and log in on web, staff and admins log in on web-admin, and the API enforces 401/403 role and hotel-access checks.

**Architecture:**
- An additive `Session` table stores sha256 hashes of opaque tokens. Web and admin use separate audiences and cookies (`sid` / `admin_sid`).
- An auth service owns every Prisma access. Middleware resolves the session into a typed `req.auth`.
- `requireRole` and `requireHotelAccess` gate admin routes, and `express-rate-limit` guards the credential endpoints.
- Both frontends get a `features/auth` slice (fetchers, `useMe`, a guard) and react-hook-form forms.

**Tech Stack:** Express 5, Prisma 7, zod v4, express-rate-limit, node:test + supertest, Next.js 16, TanStack Query v5, axios, react-hook-form + @hookform/resolvers.

**Spec:** `docs/superpowers/specs/2026-11-12-auth-design.md`. It is binding for every file's responsibility, the endpoint table, the exact messages, and the test list. Read it first.

## Global Constraints

- **Cookies and lifetimes:** `sid` belongs to audience `WEB`, lifetime 30 days. `admin_sid` belongs to audience `ADMIN`, lifetime 12 hours. Flags: `httpOnly`, `SameSite=Lax`, `Path=/`, and `Secure` only when `NODE_ENV=production`.
- **Messages (verbatim):**

  | Situation | Message |
  | --- | --- |
  | 401 | `"Authentication required"` |
  | Login failure (401) | `"Invalid email or password"` |
  | 403 (wrong role) | `"Insufficient permissions"` |
  | 403 (customer on admin login) | `"Staff access only"` |
  | 403 (hotel access) | `"No access to this hotel"` |
  | 409 | `"Email already registered"` |
  | 429 | `"Too many attempts, try again later"` |

- **Error codes:** existing codes, plus `RATE_LIMITED`.
- **Dependencies:** only these new ones are approved:
  - `express-rate-limit` (apps/api)
  - `react-hook-form` and `@hookform/resolvers` (apps/web, apps/web-admin)
- **Prisma, types and safety:**
  - Only services import `prisma`.
  - `passwordHash` is read only inside `login`, via `omit: { passwordHash: false }`.
  - No response ever contains `passwordHash`.
  - TypeScript strict, no `any`, no casts in production code.
- **Schema:** change it only through `schema.prisma` and a new additive migration. Never edit applied migrations.
- **Tests:** they run against the dev DB.
  - Seeded users are read-only: `admin@booking.local`, `staff@booking.local`, `customer@booking.local`, all with password `Password123!`.
  - Test users use emails `auth-test+<ts>-<n>@test.local`.
  - Every row a test creates is deleted in `after()`.
- **Skills:**
  - Task 1: `prisma-cli`
  - Tasks 1–3: `prisma-client-api`
  - Tasks 4–5: `tanstack-query-best-practices`, `shadcn`, `impeccable`, `next-dev-loop`
- **Commits:** before each commit, run `git status`. After it, run `git show --stat HEAD` and check that every file listed for the task is in the commit.

## Review Focus

1. Mixed-case email: logging in as `Customer@Booking.Local` must work, because emails are normalised to lowercase. Pinned in Task 2.
2. Open redirect: `?next=//evil.com` or `?next=https://evil.com` must land on `/`. Pinned in Task 1 (`safeNextPath` test).
3. Passwords are not trimmed: `"  Password123!  "` is a different password from `"Password123!"`. Pinned in Task 1 (shared schema test).
4. A duplicate email in a race must still give 409 `"Email already registered"`, not a generic `"Resource already exists"`. The service maps P2002 on `email` itself. Pinned in Task 2.
5. Logout without a cookie, or with a stale cookie, returns 204 and clears the cookie. It never returns 401. Pinned in Task 2.
