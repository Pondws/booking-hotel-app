# Payments (Phase 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A booking becomes `CONFIRMED` only after a Stripe card payment succeeds; cancelling a paid booking refunds it in full.

**Architecture:** A `PaymentProvider` interface (`StripeProvider` for dev/prod, `MockProvider` for `npm test`) sits behind `payment.service.ts`. The API creates/reuses a PaymentIntent and returns its `clientSecret`; the browser confirms it with the Payment Element; Stripe's signed webhook (and an owner-only sync endpoint) feed `settlePayment`, the single place that moves a payment out of `PENDING` and confirms or refunds the booking.

**Tech Stack:** Express 5, Prisma 7 (PrismaPg), Postgres 18, `stripe` (Node SDK), Next.js 16, TanStack Query, `@stripe/stripe-js`, `@stripe/react-stripe-js`, node:test + supertest.

**Spec:** `docs/superpowers/specs/2026-11-15-payments-design.md` — read it first; this plan argues from it.

## Global Constraints

- Dependencies approved: `stripe` (api), `@stripe/stripe-js` + `@stripe/react-stripe-js` (web). No others. Install the current versions with `npm i <pkg> -w <workspace>` from the repo root (single root lockfile).
- Cards only: every PaymentIntent is created with `payment_method_types: ["card"]`.
- Amount/currency always from the DB row (`booking.totalAmount`, `booking.currency`), never from a request.
- `settlePayment` is the only code that changes a `Payment` out of `PENDING` (cancel's refund/cancel-intent step excepted, see Task 6).
- Never log or return `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, or card data. `clientSecret` only goes to the booking's owner.
- Env: `PAYMENT_PROVIDER` = `stripe` | `mock` (default `stripe`); `mock` rejected when `NODE_ENV=production`; `STRIPE_SECRET_KEY` + `STRIPE_WEBHOOK_SECRET` required when `stripe`. `.env.test` sets `PAYMENT_PROVIDER=mock`. Web: `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`.
- Copy (verbatim): not payable → `409 CONFLICT` "This booking can't be paid"; web without publishable key → "Payments aren't configured"; test note → "Test mode — card 4242 4242 4242 4242, any future date, any CVC"; cancel dialog for paid booking → "You'll get a full refund of {total}".
- Follow CLAUDE.md layering (route → controller → service → prisma), `validate` middleware, `AppError`, `{ data }` envelope, `DESIGN.md` for UI.
- Tests: unique label per file, clean up in `after()`, never touch seeded rows. Delete `payments` before `bookings` in every cleanup (FK is `Restrict`).
- Before finishing: `npm run lint && npm run typecheck`, `npm test`, `npm run db:check` all pass.

## Review Focus

1. **Webhook and sync settle the same intent at the same moment** → exactly one settlement, booking `CONFIRMED`, no refund. Test in Task 4 (`settles once when two settlers race`).
2. **Customer pays in a second tab / double-clicks Pay** → one `Payment` row, same `clientSecret` both times. Test in Task 5 (`two concurrent starts share one payment`).
3. **Webhook body parsed as JSON before signature check** (raw body lost) → every real webhook would 400. Test in Task 5 posts a signed raw body through the full `app` and expects 200.
4. **Stripe retries a webhook after a refund already went through** → second call is a no-op, 200, not a 500 loop. Test in Task 4 (`refund retry is idempotent`).
5. **Seeded / Phase-4 `CONFIRMED` bookings with no payment get cancelled** → cancel succeeds, no provider call. Test in Task 6.

### Task 4: `settlePayment`

**Files:**
- Create: `apps/api/src/services/payment.service.ts`
- Test: `apps/api/src/services/payment.service.test.ts` (label `pay-svc`)

**Interfaces:**
- Consumes: Task 1 index, Task 3 `PaymentProvider`/`MockProvider`/`toMinorUnits`.
- Produces:
  ```ts
  export type SettleOutcome = "SUCCEEDED" | "FAILED";
  export type SettleResult = "confirmed" | "refunded" | "failed" | "noop";
  export async function settlePayment(providerRef: string, outcome: SettleOutcome, now?: Date,
    opts?: { provider?: PaymentProvider }): Promise<SettleResult>;
  ```
  Algorithm (spec "Settling"):
  1. Load payment by `providerRef` (+ booking id). Missing → log, `"noop"`.
  2. `SUCCEEDED`: `getIntent(ref)`; amount/currency ≠ row → log, `"noop"` (stays `PENDING`).
  3. `$transaction`: `payment.updateMany WHERE providerRef, status PENDING → { status, paidAt: now }` (FAILED: no `paidAt`). Count 0 → go to the retry check in step 5, else `"noop"`. For SUCCEEDED, `booking.updateMany WHERE id, status PENDING, expiresAt > now → CONFIRMED, expiresAt null`. Count 1 → `"confirmed"`.
  4. FAILED → `"failed"`.
  5. Refund path — runs **after commit** when the claim succeeded but the booking wasn't confirmed, **and** on any call that finds the payment `SUCCEEDED` while its booking isn't `CONFIRMED` (retry after a failed refund): `provider.refund(ref, { idempotencyKey: "refund-" + payment.id })` → `payment.updateMany WHERE id, status SUCCEEDED → REFUNDED, refundedAt: now` → `"refunded"`. Refund throws → log with booking code, rethrow (webhook answers 500, Stripe retries; idempotency key makes the retry safe).

- [ ] **Step 1: Failing tests** (create fixture booking `PENDING`, `expiresAt = now + 10 min`, a `Payment` row `PENDING` with `providerRef` from `mock.createIntent`):
  - `confirms the booking on success` → `"confirmed"`, booking `CONFIRMED`, `expiresAt` null, payment `SUCCEEDED`, `paidAt` set
  - `is a no-op when repeated` → second call `"noop"`, nothing changes, `mock.refunds` empty
  - `settles once when two settlers race` → `Promise.all` of two calls → results sorted `["confirmed", "noop"]`, booking `CONFIRMED`, `mock.refunds` empty
  - `refunds a success after the hold lapsed` → booking `expiresAt = now - 1 min` → `"refunded"`, booking not `CONFIRMED`, payment `REFUNDED` + `refundedAt`, `mock.refunds` = `[ref]`
  - `refund retry is idempotent` → `mock.failNextRefund = true`; first call rejects; payment still `SUCCEEDED`; second call → `"refunded"`; third → `"noop"`; `mock.refunds.length === 1`
  - `leaves amount mismatch pending` → `mock.setAmount(ref, 1)` → `"noop"`, payment `PENDING`
  - `marks FAILED` → `"failed"`, booking still `PENDING`
  - `unknown ref` → `"noop"`
- [ ] **Step 2: Run** — Expected: FAIL (module missing).
- [ ] **Step 3: Implement `settlePayment`** as above.
- [ ] **Step 4: Run** `npm test` — Expected: PASS.
